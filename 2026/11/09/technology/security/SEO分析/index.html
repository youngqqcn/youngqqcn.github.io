这是 Histats（免费访客统计服务）的计数图，5050800 是统计账号 ID。它在 Sky 原模板里不存在，是攻击者加的，用来统计每个垃圾页吸引了多少访客。这个 ID 对举报有用，Histats 可以据此定位到账号。

其余内容是什么

整个文件约 1600 行、124 KB，其余都是复制的 Sky Sports 页面：

  • 导航、页脚、登录模板、Adobe / Google Analytics / Qualtrics / DotMetrics / Covatic 等脚本，全是 Sky 自己的。
  • 这些脚本里很多用的是相对路径（如 /js/modules-es6/...、/css/...），放在 github.io 上会 404，页面样式和功能其实是坏的。攻击者不在乎，因为这个页面主要给搜索引擎爬虫看的，真人访客一般在样式加载前就被脚本带走了。

krpano 漏洞说明

我先查一下这个漏洞的官方信息，避免凭记忆说错。

漏洞是什么

krpano 是一款做全景图和 VR 漫游的播放器，很多政府、高校、企业网站的”全景导览”页面都在用。你遇到的问题是它的一个反射型 XSS（跨站脚本）漏洞，核心在 URL 里的 xml= 参数。

原理很简单：

  • https://data.cqna.gov.cn/vr/jiedao/ns/tour.html 这个页面是政府站 data.cqna.gov.cn 的一个全景导览页面，用 krpano 播放。
  • krpano 页面的配置是 XML 文件，正常情况下由网站自己指定。
  • 如果网站设置允许通过 URL 的 xml= 参数传入配置，攻击者就可以构造链接，让页面加载他指定的内容。
  • 你最初那条链接里 xml=data:video/mp4;base64,... 就是这么做的：用 data: URL 把一段 Base64 编码的 XML 直接塞进参数里，再让它去 include 攻击者 GitHub 上的文件。
  • krpano 的 XML 能调用 JavaScript，所以最终等于在政府网站的域名下执行攻击者的脚本。

公开记录

  • 2020 年就有相关漏洞披露：krpano 1.20.8 及以前版本的默认安装存在反射型 XSS，原因是 /viewer/krpano.html 对 xml 参数的外部 XML 加载不安全（CVE-2020-24900）。
  • 官方当时的修补并不彻底。SecurityWeek 报道称，这个缺陷自 2020 年就为人所知（CVE-2020-24901），开发者当时加了一些限制，但补丁不完整，影响也被低估。
  • 2025 年又有新编号：1.23.1 及以前版本在 passQueryParameters 函数中，因 xml 参数处理不当导致 XSS（CVE-2025-65892），升级到 1.23.2 可以消除。
  • krpano 作者的说法是：自 2021 年 9 月的 1.20.10 起，所有版本默认都把 passQueryParameters 设为关闭或无害值，正常情况下不该再受 XSS 影响，只有显式允许 xml 通过查询参数传入时才有风险，而这种配置很罕见。

和你这个案例的关系

SecurityWeek 报道的就是同一类手法：攻击者利用这个 XSS，把访客从大机构网站的页面重定向到任意域名，并用 SEO 投毒引流，目的地包括成人内容、赌场、黑客服务等可疑站点。你看到的”政府站 → 跳转 → 盗版直播”是同一套打法，只是换成了体育赛事关键词。

进一步排查

在Google搜索 site:data.cqna.gov.cn live，返现大量类似的SEO投毒链接

为什么能在Google搜索中看到这个链接

简单说：Google 不需要网站所有者的同意，只要有人把这个链接放到它能爬到的地方，它就会去抓。 具体怎么做的我没法确认，下面分”能从截图验证的”和”合理推断的”两部分。

一、你的截图本身就是证据

搜索结果里显示的内容，和我们读到的 GitHub 源码完全对得上：

  • 标题：LIVE Twente vs Ajax Football Live fRee Reddit，就是 GitHub 页面的 <title>。
  • 摘要：”Everything you need to know about the Twente vs Ajax. Find score, results…”，就是那页的 meta description。
  • **站点名显示为 “Sky Sports”**：政府站的名字后面跟着 Sky Sports，是因为仿冒页里写了 og:site_name、application-name 都是 “Sky Sports”。
  • 视频缩略图：来自页面里伪造的 VideoObject 结构化数据。

这说明 Google 抓到并渲染了 JavaScript 执行后的内容：政府站的 krpano 页面加载 XML，XML 里的脚本把 GitHub 上的假页面 document.write 进来，Google 的渲染器把它当成了这个 URL 的正文。所以 Google 眼里，data.cqna.gov.cn 的这个地址就是一篇”Twente vs Ajax 直播”页面。

二、链接是怎么被 Google 发现的（推断）

Google 主要靠顺着链接爬。一个带参数的恶意 URL，对 Google 来说只是普通网址，不需要在目标站上做任何手脚。攻击者要做的只是让这个链接出现在 Google 常爬的地方，常见做法有：

  • 在论坛、博客评论、留言板、问答站批量发带链接的垃圾帖
  • 搭建或租用一批站群，互相链接
  • 在 GitHub、Pastebin、社交平台等高频被爬的地方放链接
  • 用自动化工具批量生成，每场比赛换一批 id

SecurityWeek 对同类攻击的描述是：攻击者利用 SEO 投毒，把用户引到承载恶意重定向的页面上。手法一致，但我没有看到这次具体用了哪些外链，所以这部分是基于常规做法的判断。

三、为什么能排得靠前

因素 说明
高权重域名 .gov.cn 在搜索系统里信誉高，借它的权重，新页面不用从零积累
每个参数都是新页面 id= 不同就是不同的 URL，一个漏洞页面可以”长出”无限个关键词页
URL 里就带关键词 video-live-twente-vs-ajax-football-live-free-reddit... 本身就是关键词匹配
热点时效 比赛前后”live”类搜索量暴涨，竞争的正规页面反而少
长尾词 “twente vs ajax live free reddit” 这类词，正规站点不会专门去做

你截图里 “11 hours ago””17 hours ago” 说明这些页面被很快抓取、收录，符合”赛前集中投放”的节奏。

四、为什么 Google 没及时拦住

这是我的推测，没有 Google 内部信息：

  • 页面内容靠 JavaScript 加载，爬虫要渲染后才看得到，检测比抓静态页面更难。
  • 这些页面生命周期极短，比赛一结束就没价值，等反垃圾系统识别并处理时，流量已经赚完了。
  • 每次换 id、换账号，规则很难一刀切。
